# E0009: an invalid char literal

A char literal is one Unicode scalar value between single quotes (`r[lex.lit.char]`), written as the character itself or as one escape (`r[lex.lit.char.escapes]`): `'a'`, `'é'`, `'\n'`, `'\''`, `'\u{1F600}'`. This error is a char literal that is empty, holds more than one scalar value, or has no closing `'` on its line.

```
fn f() -> List<String> {
  let empty = ''
  let word = 'hello'
  [word]
}
```

Text goes in a `"` string:

```
fn f() -> List<String> {
  let empty = ""
  let word = "hello"
  [word]
}
```

A letter followed by a combining accent is two scalar values, even when it shows as one character, so `'é'` written that way is this error. Write the single scalar value, such as `'\u{E9}'`.

For more than one character, the fix makes the literal a `"` string with the same text: it unescapes `\'` and escapes `"` and `{`, so the string neither ends early nor interpolates. It needs review, because a `Char` and a `String` are different types. There is no fix when the body has an invalid escape, or when a name character or a `"` comes right before the `'`, since the new `"` would join it, as a literal's prefix or as more quotes. An empty or unclosed char has no fix, because only the author knows the character meant.

A char literal with no closing `'` ends at its line ending, so the next line is still checked. When a carriage return not followed by a line feed ends it, only that is reported, as E0013.
