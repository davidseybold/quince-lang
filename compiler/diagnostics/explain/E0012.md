# E0012: a multi-line string layout error

A multi-line string's text goes on the lines between its `"""` lines, and the closing line's indentation is what every line drops:
- After the opening `"""`, only spaces and tabs may come before the line break (`r[lex.lit.multiline-open]`).
- The closing `"""` starts its own line, after its indentation, and `"""` can't appear anywhere else in the string unless an escape takes it, as in `\"""` (`r[lex.lit.multiline-quotes]`).
- Every line between must start with exactly the closing line's indentation, the same spaces and tabs, except a line that holds only whitespace (`r[lex.lit.multiline-indent]`).

```
fn f() -> List<String> {
  let a = """Hello
    world
    """
  let b = """
    first
  second
    """
  [a, b]
}
```

Start the text on the line after the opening `"""`, and indent every line at least as far as the closing `"""`:

```
fn f() -> List<String> {
  let a = """
    Hello
    world
    """
  let b = """
    first
    second
    """
  [a, b]
}
```

Text on one line between `"""` quotes, as in `"""Hello"""`, is reported once, and the string ends at the second `"""`.

Quotes after text also end the string there, so the code after them is still checked:

```
fn f() -> String {
  let usage = """
    quince test"""
  usage
}
```

The fix moves the quotes to a line of their own, indented as the string's lines share. It needs review, because the quotes may have been meant as text: in a `"""` string, write those as `\"""`. An `r"""` string can't hold them.

Each line indented less than the closing line, or with tabs where it has spaces, gets its own error. When no line starts with the closing line's indentation, the closing `"""` is what is out of place, so the error is reported once, there.

Apart from that one, there is no fix, because moving text between lines or changing indentation can change the string's value.
