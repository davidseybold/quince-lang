# E0005: an unclosed multi-line string

A multi-line string sits between `"""` lines (`r[lex.lit.string.multiline]`), and it ends at the first line that starts with `"""` after its indentation (`r[lex.lit.multiline-close]`). One with no such line runs to the end of the file.

```
fn f() -> String {
  let usage = """
    quince build
    quince test"""
  usage
}
```

A `"""` after other text on its line is text, unlike in Java and Kotlin, so this string has no closing line. Put the closing `"""` on a line of its own:

```
fn f() -> String {
  let usage = """
    quince build
    quince test
    """
  usage
}
```

When a line holds `"""` after text, as here, the error is at those quotes, and the string ends there, so the code after it is still checked. The fix moves them to a line of their own, indented as the string's lines share, which gives the value a Java or Kotlin reader expects. It needs review, because a `"""` after text may have been meant as text, with the closing line forgotten.

With no such line, the error is at the opening `"""`, and there is no fix, because the lexer can't tell where the string was meant to end. Since the rest of the file is probably code, not text, it isn't checked for escapes or interpolation, so one missing line doesn't bring an error for every backslash and brace after it.
