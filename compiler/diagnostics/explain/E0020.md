# E0020: a comparison or range that chains

Comparison operators don't chain (`r[expr.op.compare.no-chain]`), and neither do ranges (`r[expr.op.range.no-chain]`). The error is at the operator that would chain, and a chain is one error, however long it is.

```
let inside = 0 <= i < n
let r = 0..n..10
```

Join comparisons with `&&`:

```
let inside = 0 <= i && i < n
```

The fix writes that, repeating each middle operand. It needs review, since an operand that calls something now runs twice. It is offered only when the chain's operators point the same way: `<` with `<=`, `>` with `>=`, or `==` with `==` (`r[expr.op.compare.split]`). A chain that mixes them, such as `a < b > c` or `g<1>(x)`, or that holds `!=` or `is`, has no fix, since repeating its middle operand rarely gives what was meant. There is no fix either when a middle operand holds a comment or a line break, and none for a chained range, since only you know which range you meant.
