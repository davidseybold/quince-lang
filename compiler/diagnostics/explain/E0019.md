# E0019: an operand that needs parentheses

Some operators can't be an operand of a different operator without parentheses (`r[expr.op.parens-required]`), so every expression that compiles reads one way:

- `&&` and `||` can't be mixed (`r[expr.op.logic.no-mix]`).
- `&`, `|`, `^`, `<<` and `>>` have no level. Each must be in parentheses as an operand of any other operator, and its own operands are prefix or postfix expressions (`r[expr.op.bits.parens]`). `&`, `|` and `^` chain only with themselves (`r[expr.op.bits.chain]`), and a shift doesn't chain.
- A range must be in parentheses as an operand (`r[expr.op.range.parens]`).

```
let tested = flags & MASK == 0
let mask = 1 << n - 1
let ok = a || b && c
let found = r == 0..3
```

Add the parentheses:

```
let tested = (flags & MASK) == 0
let mask = 1 << (n - 1)
let ok = a || (b && c)
let found = r == (0..3)
```

The error is at the operand that needs them. The fix adds them where the usual reading puts them: arithmetic binds tighter than the bit operators, which bind tighter than ranges, comparisons, `&&` and then `||`. It needs review, since you may have meant the other reading, such as `(a || b) && c`.
