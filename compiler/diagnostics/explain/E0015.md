# E0015: a control or bidirectional-format character in a literal or comment

Apart from tabs and line endings, a literal or comment can't hold a control character (U+0000 to U+001F, and U+007F) or a bidirectional-format character (U+202A to U+202E, U+2066 to U+2069) (`r[lex.source.control]`). These characters are invisible, or they change the order in which an editor shows the text around them, so code that holds them can read differently from how it runs. Outside literals and comments, source is ASCII, and such a character is an E0001 instead.

A `"` or `"""` string writes one as an escape. This string holds U+202E, a right-to-left override, written as itself (shown here as `<U+202E>`), so an editor shows the text after it reversed, as `txet`:

```
fn f() -> String {
  "<U+202E>text"
}
```

Write it as its `\u{...}` escape:

```
fn f() -> String {
  "\u{202E}text"
}
```

A test's name and a char literal write one the same way, as in `'\u{7}'`. A bytes literal writes a control character as a `\x` escape, as in `b"\x07"`. A bidirectional-format character isn't ASCII, so in a bytes literal it is an E0011, whose fix writes the `\x` escapes of its UTF-8 bytes.

Raw strings, tagged literals and comments have no escapes, so they can't hold these characters at all. Move the text to a `"` string, or delete the character.

A run of these characters is one error. In a `"` or `"""` string, a test's name, a char literal or a bytes literal, the fix writes each character as its escape, and is safe, since the value stays the same. In a char literal that holds more than one character, which is also an E0009, apply this fix first: E0009's fix, which makes it a string, waits until it has. There is no fix in an interpolation's braces, where an escape would still be an error. A character inside an invalid escape, as in `\` followed by U+0007, is part of that escape, which E0006 reports.

The text after an opening `"""`, and the lines of a `"""` string with no closing line, aren't checked for these characters, as they aren't checked for escapes: E0012 or E0005 reports the string first.
