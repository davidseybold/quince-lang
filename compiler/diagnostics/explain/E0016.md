# E0016: a token that can't go here

The code doesn't follow Quince's grammar: the message says what may go at this point and what was found instead. It covers every syntax error that has no code of its own.

```
fn match() {}

fn f(a: Int, b: Int) {
  let total = g(a
    b)
  let s = "press "b" now"
}
```

`match` is a keyword, and a keyword can't name a function, a parameter, a binding, a field or a method (`r[lex.keyword-not-name]`). The arguments of a call are separated by commas, and two expressions can't share a line, since a statement ends at its line break (`r[lex.line-end]`):

```
fn check() {}

fn f(a: Int, b: Int) {
  let total = g(a,
    b)
  let s = "press \"b\" now"
}
```

When an item of a list is followed, on the next line, by something that starts another item, the fix inserts the missing `,`. It needs review, because the two lines may have been meant as one item. Only a function type may be written in parentheses (`r[type.fn-parens]`), so for one other type in parentheses, such as `(Int)`, the fix removes them, safely. Otherwise there is no fix.

After this error the parser skips to the end of the line, or to the next `,` in a list, and reports nothing more until it gets there, so one mistake gives one error. A bracket it skips is skipped whole, up to its closing bracket.
