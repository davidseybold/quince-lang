# E0004: an unclosed string

A `"` string stays on one line (`r[lex.lit.string.one-line]`), so one with no closing `"` before its line ends is an error. The string ends at the line end, and the next line is code again, so one missing quote can't hide the rest of the file.

```
fn f() {
  let greeting = "hello
  let name = "world"
}
```

Close the string on its line:

```
fn f() {
  let greeting = "hello"
  let name = "world"
}
```

Text over several lines goes between `"""` lines instead.

The fix inserts `"` at the end of the line and needs review, because the string may have been meant to end earlier, before a comment for example. There is no fix when the line ends with a `\`, since a `"` after it would be escaped, and E0006 reports the `\`. A carriage return with no line feed after it also ends the string, and then only E0013 is reported.
