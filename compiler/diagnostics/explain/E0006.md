# E0006: an invalid escape

A `"` string takes only these escapes (`r[lex.lit.string.escapes]`): `\n`, `\t`, `\r`, `\0`, `\\`, `\"`, `\{` and `\u{...}`. Anything else after a `\` is an error:

- an unknown escape, such as `\q`, or `\p` in a Windows path written with single backslashes;
- `\'` and `\}`, since a `'` and a lone `}` need no escape in a string (`r[lex.lit.string.lone-brace]`);
- a `\u{...}` that isn't one to six hex digits naming a Unicode scalar value (`r[lex.lit.string.unicode-escape]`): `\u{}`, a surrogate such as `\u{D800}`, a value above `\u{10FFFF}`, or a `\u` with no braces;
- `\x`, which appears only in bytes literals (`r[lex.lit.bytes.hex-escape]`);
- a `\` at the end of a line, which escapes nothing.

A char literal takes the same escapes plus `\'` (`r[lex.lit.char.escapes]`), so the list above holds there too, apart from `\'`. A bytes literal takes `\x` with two hex digits, `\n`, `\r`, `\t`, `\0`, `\\` and `\"` (`r[lex.lit.bytes]`), so any other escape is an error there, `\u{...}`, `\{`, `\'` and `\}` included.

```
fn f() {
  let path = "C:\docs\quince"
  let quote = "it\'s"
  let letter = "\x41"
}
```

```
fn f() {
  let path = "C:\\docs\\quince"
  let quote = "it's"
  let letter = "\u{41}"
}
```

For `\'` and `\}`, the fix deletes the backslash, which leaves the text the escape was meant to be. The other forms have no fix, because only the author knows the intended text: `"C:\temp"` holds a valid `\t`, so the lexer can't tell that it was meant to be a path.
