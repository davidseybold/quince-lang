# E0018: a line break that ends a statement too early

A line break ends a statement unless the line ends with a binary operator, a comma or an opening bracket (`r[lex.line-end]`). So a long expression breaks after its operator, never before. A line that starts with something that can't start a statement, but would continue the one above, is an error:

```
let total = price
  + tax
if ready
{
  start()
}
```

The same goes for `=` or a compound assignment, `?`, and a body's `{` at the start of a line. `else` goes on the line of the closing `}` (`r[lex.else-same-line]`), inside brackets too:

```
if ready {
  start()
}
else {
  wait()
}
```

Join the lines:

```
let total = price + tax
if ready {
  start()
} else {
  wait()
}
```

The fix joins them, safely, by replacing the line break and the indentation after it with a space. There is none when a comment lies between the two lines, since joining would move code into the comment or delete it, and none when the line above ends with type arguments, as in `make<Int>`, that joining would turn into a comparison. A line that starts with `-` is a new statement, since `-` can start an expression, and so is one after a `;`.
