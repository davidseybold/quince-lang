# E0014: a source file that isn't UTF-8

A Quince source file is UTF-8 text (`r[lex.source.utf8]`). This error is reported once for each line that holds bytes that don't decode, at the first run of them on that line. The message lists the bytes.

The compiler goes on checking the rest of the file, reading each run of invalid bytes as one U+FFFD replacement character. That text is no longer the file, so no tool writes it back: `quince fmt` and `quince fix` leave such a file alone, and no other error in the file offers a fix until its bytes are UTF-8.

There is no fix. The usual causes are a file saved in another encoding, such as Latin-1 or UTF-16, which an editor can convert to UTF-8, and a binary file passed by mistake.
