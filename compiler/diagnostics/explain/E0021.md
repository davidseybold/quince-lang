# E0021: a name of the wrong case where it's declared

Each kind of name has one case, and the compiler checks it where the name is declared (`r[lex.name.case]`, `r[lex.name.enforced]`, `r[lex.name.declared]`). The cases are defined by `r[lex.name.snake]`, `r[lex.name.pascal]` and `r[lex.name.screaming]`:

- `snake_case` for functions, parameters, bindings, fields and package names: lowercase letters, digits and single underscores between them, starting with a letter.
- `PascalCase` for types, interfaces, effects, variants, type parameters and effect variables: an uppercase letter first and no underscores. A name of two or more letters needs a lowercase letter, so a type is `Url`, not `URL`.
- `SCREAMING_SNAKE_CASE` for constants: uppercase letters, digits and single underscores between them, starting with a letter, with at least two letters.

```
const maxRetries: Int = 3

fn ParseUrl(_input: String) -> Url {
  ...
}
```

Write each name in its case:

```
const MAX_RETRIES: Int = 3

fn parse_url(input: String) -> Url {
  ...
}
```

A name that fits no case, such as `_input`, can't be declared. An unused parameter or binding is `_`. A one-letter constant such as `N` needs a longer name, such as `SIZE`.

Names declared in a `foreign` block keep their C spelling, and code uses them in that spelling (`r[lex.name.foreign-exempt]`).
